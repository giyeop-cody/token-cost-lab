## 1. 트리거는 고쳐진다 — 0/5 → 4/5, 거짓양성 0

### 무엇이 틀렸었나

| 실패 유형 | 현행 패턴이 요구한 것 | 실제 발화 |
|---|---|---|
| 명사구 누락 | `(이거\|그거\|이렇게)\s*말고` | **"복잡한 거 말고"** |
| 부사 삽입 | `처음부터\s*다시` | **"처음부터 심플하게 다시"** |
| 반려어 부재 | (해당 패턴 없음) | **"저장이 안 돼", "클릭해도 안 열려"** |

앞의 둘은 정규식 보강으로 끝난다. **문제는 세 번째다.**

### 증상 신고를 텍스트만으로 잡으면 붕괴한다

`안 되/사라져/에러` 류를 패턴에 넣으면 실로그 검출은 2/5 → 4/5로 오르지만,
반려가 아닌 발화까지 걸린다:

```
!  이 API는 인증 없이는 안 되니까 토큰 발급부터 해줘
!  구형 브라우저에서 안 되는 문법은 피해줘
!  정렬이 안 되는 케이스도 테스트에 넣어줘
!  에러 핸들링 추가해줘
!  오류 메시지를 한국어로 바꿔줘
   → 거짓양성 5/6
```

거짓양성 1건은 곧 **B 사다리 1칸($0.0286)을 헛되이 태우는 것**이다.
잡은 것보다 흘린 게 많아진다.

### 해법 — 문장이 아니라 대화 상태로 가른다

"안 된다"가 반려인지 신규 지시인지는 문장만으로 안 갈린다.
갈리는 건 **직전 턴에 내가 그걸 만들었는가**이다. 두 조건을 겹쳤다:

1. **요청 어미로 끝나면 신규 지시** — `~해줘/넣어줘/피해줘/추가해`로 끝나는 건
   앞으로 만들 것에 대한 요구사항 서술이지 이미 만든 것에 대한 반려가 아니다.
2. **직전 산출물의 개념어와 겹칠 때만 반려** — `artifact_terms`와 내용어 교집합.

```python
def looks_symptom(text):            # router.py
    return bool(_SYMPTOM_PAT.search(t)) and not _REQUEST_TAIL.search(t)

symptom = looks_symptom(command) and (terms & _content_words(command))   # ladder_b.py
```

| 판정기 | 실로그 검출 | 거짓양성 |
|---|---:|---:|
| 현행 | **0/5** | 0/10 |
| 정규식 보강만 | 2/5 | 0/10 |
| 보강 + 증상신고(텍스트만) | 4/5 | **5/6** ✗ |
| **보강 + 증상신고 + 대화상태** | **4/5** | **0/10** ✓ |

못 잡은 1건은 턴3 `"디자인이 너무 밋밋한데 다크 테마로 해줘"` — **취향**이다.
분류기가 `taste`로 잡고 "티어 올리지 마라"고 판정하는 항목이라, B 사다리가
안 도는 게 오히려 정답이다.

### 수정 후 실로그 재생

```
턴1 proceed   first          MID   unit
턴2 escalate  widen          MID   file    explicit
턴3 proceed   new-intent     MID   unit            ← 취향, 정상적으로 통과
턴4 escalate  widen          MID   file    symptom
턴5 escalate  tier-up        LARGE file    symptom
턴6 escalate  widen-2        LARGE module  explicit
```
대조군 페르소나 B(반려 0회)는 **에스컬레이션 0회** — 거짓양성 없음.

## 2. 그런데 B가 턴4·5를 처리하는 건 옳지 않다

트리거는 고쳐졌지만, 고치고 나니 **B가 자기 관할이 아닌 걸 가져간다.**

### 반려 5턴의 관할 분해

로그의 어시스턴트 자백 문장을 근거로 원인을 특정했다.

| 턴 | 원인 | 관할 | 근거 |
|---|---|---|---|
| 2 | 스펙 미합의(원하는 형태를 안 말함) | **B** | AC로 못 만든다. 사용자가 봐야 안다 |
| 3 | 취향 | 어느 쪽도 못 고침 | 예시 제시로 해결 |
| 4 | 이벤트 핸들러에서 `save()` 미호출 | **A** | 결정론 AC로 잡힌다 |
| 5 | 렌더 후 리스너 재등록 누락 | **A** | 결정론 AC로 잡힌다 |
| 6 | 턴2~5 누적 결과 전면 재작성 | 파생 | 앞을 막으면 발생 안 함 |

턴4·5는 페르소나 B의 스펙에 이미 적혀 있던 완료조건이다:
`새로고침 후 데이터 유지` · `목록 클릭 시 정상 로드`.
최종 산출물 `demo/memo.html`로 검사식을 돌리면 **둘 다 결정론적으로 PASS 판정**된다.
즉 **AC 두 줄이면 사용자에게 나가기 전에 턴 안에서 잡혔을 결함**이다.

### 같은 두 턴, 처리 주체에 따른 비용

| 처리 | 비용 | 비고 |
|---|---:|---|
| A 사다리 retry ×2 | **$0.0225** | 턴 내부에서 끝, 사용자 시간 0 |
| B 사다리 widen + tier-up | **$0.1180** | 사용자가 2번 왕복 |

**B가 5.2배 비싸다.** 게다가 B는 턴5에서 티어를 LARGE로 올렸는데,
실제 원인은 "리스너 재등록 누락"이라 **모델 능력 문제가 아니다.**
돈만 쓰고 같은 실수를 반복할 자리다.

## 3. 결론 — 서열이 실측으로 확정됐다

| 구성 | 비용 | 절감 | 성격 |
|---|---:|---:|---|
| 장치 없음 (실측) | $1.0361 | — | 리워크 5턴 |
| **B 단독** | $0.2432 | 4.3배 | 기능결함까지 사용자 왕복으로 처리 |
| **A+B 결합** | **$0.0624** | **16.6배** | A가 선제 차단, 못 잡은 것만 B |
| 스펙 선주입 (실측) | $0.0498 | 20.8배 | 애초에 반려를 안 만듦 |

### 세 문장으로

1. **A는 싸고 관할이 좁다.** 결정론 AC로 표현되는 것만 잡지만,
   잡히는 건 턴 안에서 $0.0112에 끝난다. 사용자 시간을 안 쓴다.
2. **B는 비싸고 관할이 넓다.** "스펙 자체가 틀렸다"는 AC로 못 만들어서
   B밖에 못 잡는다. 대신 1칸이 A의 2.6배($0.0286 vs $0.0112)이고
   사용자를 한 번 왕복시킨다.
3. **따로 쓰면 둘 다 손해다.** A만 켜면 턴2(스펙 미합의)를 영영 못 잡고,
   B만 켜면 턴4·5를 5.2배 비싸게 처리한다.
   **A를 앞에 세우고 B를 뒤에 두는 순서가 실측으로 정당화된다** —
   이건 `orchestrator.py`가 이미 구현한 중첩 구조 그대로다.

### 그리고 셋 다 이기는 것

스펙 선주입 $0.0498이 A+B 결합 $0.0624보다 **여전히 싸다.**
사다리는 잘 만들어도 **안 만든 리워크를 못 이긴다.**
발표의 순서는 이걸 반영해야 한다 — 사다리는 2번이고, 1번은 완료조건 두 줄이다.

## 4. 남은 한계

- **취향(턴3)은 어느 사다리도 못 고친다.** 예시 2~3개 제시 후 택일이 유일한 처방.
- `artifact_terms`는 호출자가 넘겨야 한다. 기본값은 앵커 명령의 내용어라
  산출물이 앵커에서 멀어지면 정확도가 떨어진다. 실제 운영에선
  **직전 턴이 건드린 파일·심볼 목록**을 넘기는 편이 정확하다.
- 표본은 실로그 1쌍(6턴+2턴)이다. 통계가 아니라 케이스다.
