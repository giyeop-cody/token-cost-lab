# 사다리 축소 — 구현과 검증 결과

> 앞선 폐기검토의 결론("폐기가 아니라 축소")을 실제 코드로 구현하고,

## 0. 먼저 정정 — 지난 턴의 "오차 61.7%"는 내 실수였다

`demo/results.json`의 A 비용 $1.0361이 라우터 비용 모델로 재현되지 않아
캘리브레이션을 실패로 보고했다. 원인은 모델이 아니라 **기준이 달랐던 것**이다.

| 항목 | 실측(`compare_personas.py`) | 내가 쓴 라우터 모델 |
|---|---|---|
| 단가 | **sonnet $3 / $15** | MID $1.25 / $10 |
| 사고 토큰 | **19,440개 출력에 포함** | 아예 계산 안 함 |

같은 기준으로 맞추면 이렇게 된다.

```
입력  79,130 × $3/M                    = $0.2374
출력  29,853 + 사고 19,440 × $15/M     = $0.7394
합계                                   = $0.9768
실측 a_cost                            = $1.0361   → 오차 5.7%
```

등차누적 가정에 `g=4,700`을 넣은 재현도 **$0.9764 (오차 5.8%)**.
남은 5.8%는 캐시 쓰기 할증 등 세부 항목 차이다.

**→ `turn_growth_tok = 4,700`은 실측으로 뒷받침되는 값이다.** 확정해서 쓴다.

## 1. 입력 누적을 넣으니 "실패 3회 역전"이 사라졌다

이전 배수표의 가장 큰 문제는 실패 3회 지점에서 사다리가 제자리 반복보다
**비싸지는(0.99배)** 구간이 있다는 것이었다. 누적을 반영하면 사라진다.

| 실패 | 제자리 반복 | 사다리 | 배수 | (누적 미반영) |
|---:|---:|---:|---:|---:|
| 1회 | $0.0625 | $0.0465 | **1.34배** | 1.43 |
| 2회 | $0.1073 | $0.0591 | **1.81배** | 1.60 |
| 3회 | $0.1611 | $0.1141 | **1.41배** | **0.99 ← 역전** |
| 4회 | $0.2239 | $0.1141 | **1.96배** | 1.27 |
| 5회 | $0.2956 | $0.1141 | **2.59배** | 1.55 |
| 6회 | $0.3764 | $0.1141 | **3.30배** | 1.78 |

**역전 구간: 없음.**

왜 사라졌나. 제자리 반복은 턴마다 이전 대화가 통째로 입력에 다시 실려
입력이 4,700토큰씩 불어난다. 사다리는 리셋 칸에서 이 누적을 0으로 끊는다.
**사다리의 우위는 "더 좋은 모델을 쓴다"가 아니라 "입력 누적을 끊는다"에서 나온다.**

사용자가 요구한 조건도 충족한다.

- **1턴 리워크: 26% 이득** ($0.0625 → $0.0465)
- **2턴 리워크: 45% 이득** ($0.1073 → $0.0591)

짧은 리워크에서 손해 보지 않는다. 실패 4회 이후 사다리는 $0.1141로 평탄해진다
(천장 도달) — 여기서 배수가 계속 벌어지는 건 제자리 쪽이 계속 비싸지기 때문이다.

## 3. 반증 — tier-up을 완전히 삭제하면 안 된다

축소안이 유리한 결과만 보고 끝내면 안 되므로, 지는 경우를 찾았다. **있다.**

정말로 모델 능력이 부족한 작업(의도불일치 5종 중 `reasoning`)에서는
축소 사다리가 못 풀고 respec까지 내려가 **사람을 부른다**.

| | 경로 | 토큰 비용 | 사람 시간 | 실질 |
|---|---|---:|---:|---:|
| 7칸 | widen 실패 → **tier-up 성공** | $0.1377 | — | **$0.1377** |
| 3칸 | widen → reset → **respec(사람 호출)** | $0.0832 | $0.50 | **$0.5832** |

토큰만 보면 3칸이 $0.0544 싸지만, 사람 시간을 넣으면 **4.2배 역전**한다.
(사람 시간 $0.50은 가정값이다 — 시급 $60 기준 30초. 이 수치는 덱에 실을 때
반드시 가정임을 밝혀야 한다.)

**그래서 tier-up은 삭제가 아니라 조건부로 되살렸다.**

```python
CONDITIONAL_TIER_UP = dict(step="tier-up", scope_up=0, tier_up=1, reset=False,
    why="분류기가 'reasoning'으로 판정했다 — 범위나 맥락이 아니라 "
        "난이도가 원인인 유일한 종류다. 이때만 모델을 올린다.")
```

`observe(..., mismatch_kind="reasoning")`일 때만 이 칸이 끼어든다.
의도불일치 5종(범위/취향/전제/판단오류/맥락오염) 중 티어 상승이 정답인 건
`reasoning` 하나뿐이므로, 상시 칸에서 빼고 조건부로 두는 것이 맞다.

동작 확인:

```
reasoning → step=tier-up  tier=LARGE   ✓
taste     → step=widen    tier=MID     ✓
미지정    → step=widen    tier=MID     ✓
```

## 5. 덱에 실을 수 있는 문장 / 실으면 안 되는 문장

**실을 수 있다:**
- "제자리에서 다시 시키면 대화가 통째로 입력에 다시 실린다. 턴당 4,700토큰씩 불어난다." (실측 역산, 오차 5.8%)
- "사다리의 이득은 좋은 모델을 쓰는 데서 나오지 않는다. 입력 누적을 끊는 데서 나온다."
- "1턴 리워크 26%, 2턴 45% 절감." (짧은 리워크에서도 이득)
- "칸을 7개에서 3개로 줄였더니 실로그에서 3.06배 저렴해졌다."
- "모델을 올려야 하는 경우는 다섯 중 하나뿐이다. 그래서 상시 칸이 아니라 조건부다."

**실으면 안 된다:**
- ~~"사다리 12배 절감"~~ — 대조군을 유리하게 잡았을 때만 나오는 수치.
- ~~"스펙 선주입이 사다리를 이긴다"~~ — 반려 0턴 vs 5턴, 축이 다르다.
- ~~"tier-up은 쓸모없다"~~ — reasoning 계열에서는 필요하다. 조건부다.
- 사람 시간 $0.50을 **가정임을 밝히지 않고** 쓰는 것.

## 6. 남은 것

- 사람 시간 $0.50은 가정값이다. 실측이 없으므로 덱에서는 감도분석
  ($0.1 / $0.5 / $2)으로 제시하는 편이 안전하다.
- 판정자 검출률(25/55/75%)은 여전히 가정값이다.
- `LEAN_LADDER`를 기본값으로 승격할지는 결정하지 않았다.
  현재는 `INTENT_LADDER`가 기본이고 축소는 선택이다.
