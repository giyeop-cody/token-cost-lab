# 사다리를 폐기하는 게 나은가

재생: `analysis/ladder_keep_or_kill.py`
결론: **전부 폐기는 아니다. 다만 지금 형태에서 남길 것은 7칸 중 2개다.**

---

## 0. 먼저 — 앞 문서의 비교는 불공정했다

앞 문서 `ladder_ab_efficacy.md` §3에 이렇게 적었다.

> A+B 결합 $0.0624 vs 스펙 선주입 $0.0498 → "사다리는 안 만든 리워크를 못 이긴다"

**이 두 숫자는 같은 세션이 아니다.**

- `$0.0624` = 반려가 5턴 터진 세션을 사다리로 처리한 비용
- `$0.0498` = 반려가 거의 안 터진 세션의 총 세션 비용

사다리와 스펙은 **대체재가 아니라 직교한다.** 같은 축에 놓고 비교한 것이 오류였고,
"폐기하는 게 낫나"라는 질문은 그 잘못된 표에서 자연스럽게 따라 나온다.
비교를 바로잡고 다시 판단한다.

---

## 1. 스펙을 잘 써도 리워크는 0이 되지 않는다

페르소나 B 로그 말미에는 "리워크 없음"이라 적혀 있다. 그런데 턴2 원문은:

> "확인함. 640px 미디어쿼리에서 목록 폭 110px이 너무 좁다. 140px로."

**이건 산출물을 보고 고쳐달라는 수정 요청이다. 성격상 리워크다.**
스펙을 아무리 잘 써도 화면을 봐야 아는 것은 남는다.
즉 스펙 선주입은 리워크를 **0으로 만드는 장치가 아니라 줄이는 장치**다.
리워크가 남는 한, 그걸 처리할 규칙은 필요하다. → **전면 폐기는 답이 아니다.**

---

## 2. 그런데 사다리의 이득은 알려진 것보다 훨씬 작았다

`router.rework_cost()`를 그대로 호출해 실패 횟수별로 비교했다.

| 실패 | 제자리 재시도 | 사다리 | 배수 |
|---:|---:|---:|---:|
| 1회 | $0.0545 | $0.0385 | 1.42배 |
| 2회 | $0.0818 | $0.0519 | 1.58배 |
| **3회** | $0.1090 | $0.1106 | **0.99배 (사다리가 더 비쌈)** |
| 4회 | $0.1363 | $0.1106 | 1.23배 |
| 6회 | $0.1908 | $0.1106 | 1.72배 |

**실패 3회 지점에서 사다리가 제자리 반복보다 비싸다.** tier-up 칸에서 LARGE로
올리는 비용이 절감을 잡아먹기 때문이다. 기존 문서들이 인용해 온 "$1.3353 → $0.1106"
같은 큰 배수는 대조군을 *전체 재출력 + 최상위 모델*로 잡았을 때의 값이고,
**공정한 대조군(제자리 재시도 + 출력 상한)에서는 1.2~1.7배**로 줄어든다.

---

## 3. 그러나 비용 모델 자체에 결함이 있었다 — 입력 누적 누락

`rework_cost()`는 매 턴 `tok_in`을 **고정**으로 둔다. 실측 페르소나 A의 입력은
**79,130토큰**까지 불어났다. 대화가 길어지면 이전 턴 전체가 다시 들어가기 때문이고,
**이게 리워크 비용의 실제 지배항**이다. 모델이 이걸 빼먹고 있었다.

입력 누적(턴마다 직전 출력 + 사용자 발화가 컨텍스트에 쌓임)을 반영해 6턴 재계산:

| 구성 | 비용 | 절감 |
|---|---:|---:|
| 폐기 — 전체 재출력, 누적 방치 | $0.2160 | — |
| 출력 상한만 | $0.0900 | 2.4배 |
| **사다리 (상한 + 리셋 2회)** | **$0.0750** | **2.9배** |

리셋이 기여한 몫은 $0.0150(17%)이다.

**사다리의 이득은 "티어를 올렸다 내렸다"에서 나오지 않는다.**
①출력 상한 ②리셋으로 입력 누적을 끊는 것, 이 둘에서 나온다.
고정 입력을 가정한 기존 표는 두 번째를 통째로 못 본다.

---

## 4. 칸 단위 판정 — 사다리는 한 덩어리가 아니다

| 대상 | 판정 | 근거 |
|---|---|---|
| **A 사다리 (AC 실패 트리거)** | **유지** | 결정론 트리거라 오탐 0. 칸당 $0.0112. 사용자 왕복 없이 턴 안에서 끝남 |
| **출력 상한 (REWORK_OUT_TOK)** | **유지 — 최우선** | 절감의 대부분이 여기서 나옴(2.4배 중 대부분). 사다리에서 이것만 남겨도 이득 |
| **리셋 (입력 누적 차단)** | **유지** | 추가 17% 절감. 단 사용자 지시대로 "완료됐는데 방향이 틀림"에서만 |
| **B 사다리 (반려 트리거)** | **관할 축소 후 유지** | 트리거 수정으로 4/5·오탐 0 확보. 단 **스펙 미합의 전용**으로 좁힐 것 |
| **B의 tier-up 칸** | **폐기** | 실로그 턴5에서 LARGE로 올렸으나 원인은 리스너 재등록 누락 — 모델 능력과 무관. 티어 상승이 정답인 건 5종 중 `reasoning` 하나뿐 |
| **B의 widen-2 / repeat 칸** | **폐기 검토** | 실패 3회 구간에서 사다리를 제자리 반복보다 비싸게 만드는 주범 |
| **respec 칸** | **유지** | $0. 구현을 멈추는 칸이라 비용이 없고 상한을 막는다 |
| **의도 불일치 5종 분류** | **유지 + 보강** | 실로그 40%. 버그신고형 6번째 종 추가 필요 |

## 5. 답

**폐기가 아니라 축소다.** 구체적으로:

1. **7칸 B 사다리는 과설계다.** 실로그에서 값을 한 이유가 확인된 칸은
   `widen`과 `respec` 둘뿐이다. tier-up은 실증 사례에서 오답이었다.
2. **A 사다리는 그대로 둔다.** 싸고, 오탐이 없고, 사용자 시간을 안 쓴다.
3. **정작 지켜야 할 것은 사다리라는 구조가 아니라 두 레버다** —
   출력 상한과 입력 누적 차단. 사다리를 다 걷어내고 이 둘만 남겨도 2.4배가 나온다.
   사다리는 "언제 그 레버를 당길지"를 정하는 껍데기다.
4. **스펙 선주입과는 경쟁 관계가 아니다.** 스펙은 리워크 발생 빈도를 낮추고,
   사다리는 발생한 리워크의 단가를 낮춘다. 둘 다 한다.

### 발표에 쓸 문장
- "사다리는 7칸이 아니라 2칸이면 된다."
- "리워크 비용의 지배항은 모델 티어가 아니라 입력 누적이다."
- "실패 3회 지점에서는 사다리가 제자리 반복보다 비쌌다" — 불리한 수치지만 실측이므로 싣는다.

### 쓰면 안 되는 문장
- ~~"사다리가 12배 절감"~~ — 대조군을 최상위 모델로 잡았을 때만 나오는 값.
- ~~"스펙 선주입이 사다리를 이긴다"~~ — 서로 다른 세션 비교. 직교하는 축이다.

---

## 6. 후속 필요

`rework_cost()`에 입력 누적 파라미터가 없다. 지금 모델은 리셋의 가치를
구조적으로 과소평가한다. **`tok_in_growth`를 추가해 재계산해야** 기존 문서의
사다리 수치 전부가 정확해진다. 이 문서의 §3은 별도 시뮬레이션으로 계산한 값이다.
