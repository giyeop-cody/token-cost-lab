# 카페 Vibe vs Spec — 산출물과 추정 usage 케이스

기록일 2026-08-15 · 정정일 2026-09-20. 표본 1쌍입니다.
**실제 API 청구 usage가 아니라 세션 토큰 추정치**를 고정하고 단가를 적용한 사례입니다.
상대 비교도 추정 오차에서 자유롭지 않습니다.

## 유지되는 숫자

| 항목 | Vibe | Spec |
|---|---:|---:|
| 비캐시 입력 (이 케이스의 정의) | 486 | 1,152 |
| 추론 추정 | 1,240 | 980 |
| 보이는 출력 추정 | 5,830 | 5,410 |
| 캐시 입력 추정 (input과 별도) | 312 | 468 |
| 합계 | 7,868 | 8,010 |
| GPT-5 단가 환산 | $0.0713465 | $0.0653985 |

토큰 **+1.8%**, 비용 **-8.3%**입니다. 같은 추정 토큰에 Sonnet $3/$15와 캐시 읽기 0.1배를
적용하면 $0.1076016 → $0.0994464, 약 **-7.6%**입니다. 이것은 다른 모델을 실행한 실측이 아닙니다.

**캐시 버킷도 추정입니다.** 312/468 같은 수치를 실제 모델의 최소 프리픽스·읽기 단위와 맞는
관측값이라고 확인하지 않았습니다. 할인 없이 추정 입력 전부를 신규 입력으로 환산하면
GPT-5 기준 **$0.0716975 → $0.0659250 (약 -8.1%)**입니다. -8.3%는 원래 캐시 가정의 산술로 보존합니다.

스펙은 Vibe 산출물을 역산했습니다. 백지 스펙 작성 비용과 실제 재작업 감소를 통제하지 않았습니다.
두 산출물이 존재하고 외관이 유사하다는 것만으로 품질 동등성을 입증하지 않습니다.
Spec-Kit 대 OpenSpec의 외부 비교 역시 둘 다 SDD라서 ‘SDD 대 무스펙’ 결과와 직접 대조할 수 없습니다.

## 가격 민감도

`r=출력/입력 단가`, `h=캐시 읽기/입력 단가`라면:

```text
Δ비용 = (입력단가 / 1,000,000) × (666 + 156h - 680r)  # 단가는 USD/1M
Spec이 저렴한 조건: r > (666 + 156h) / 680
```

h=0.1이면 손익분기는 r=1.0024입니다. 모든 상용 가격 체계에서 항상 이긴다는 뜻은 아닙니다.
고정된 이 토큰 이동에서 r→∞일 때만 약 -9.62%에 수렴합니다. 다른 작업의 절감 상한은 아닙니다.

```bash
python demo/vibe_vs_spec/sensitivity.py
```

## AC: 문자열 검사와 실제 기능을 분리

기존 16/16은 HTML/CSS **문자열/구조 검사**였습니다. 모바일을 두 열로 바꾸어도 통과할 수 있었습니다.
현재 기본 검증은 기존 정적 항목에 더해 Chromium에서 390/820/821/1280px 레이아웃,
카드 내용, 앵커의 실제 이동, 가로 스크롤과 JS 오류를 확인합니다.

```bash
pip install -r requirements-dev.txt
python -m playwright install --with-deps chromium
python demo/vibe_vs_spec/verify_ac.py
```

브라우저가 없으면 UNVERIFIED와 nonzero exit입니다. `--static-only`는 부분 검사라는 이름으로만 제공합니다.
새로운 검증이 현재 결과물을 통과시켜도 **이전 중간 실패를 예방했음**이나 **실제 품질 동등성**을 증명하지는 않습니다.
