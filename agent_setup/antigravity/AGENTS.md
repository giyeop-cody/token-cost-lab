# 토큰 라우팅 규칙

이 워크스페이스에서 작업할 때는 `token-router` MCP 서버의 판단을 따른다.

## 0. 기본값은 축소안(LEAN)이다

사다리 B(사용자 의도 반복)는 기본 3칸이다. `config.DEFAULT_INTENT_LADDER_NAME = "lean"`.

```
widen → reset → respec
```

7칸 원안(INTENT_LADDER)은 명시적으로 넘길 때만 쓰고, 라이브/발표는 모두 3칸으로
맞춘다. 사다리 A(router.REWORK_LADDER, 실패 재시도)도 이미 lean — `retry → widen → tier-up`,
한 축씩만 올린다.

## 1. 작업 시작 전 — 반드시 `route_task`

새 요청을 받으면 코드를 쓰기 전에 `route_task`를 먼저 부른다.
반환된 `tier`와 `options`를 그대로 따른다.

- `max_out_tok`이 있으면 그 안에서 끝낸다.
- `explain: 3-lines`면 설명은 3줄. 요청받지 않은 해설을 붙이지 않는다.
- `tier: web`이면 정액제 웹 세션으로 보낸다(토큰 과금 없음).
- `prefer: code-execution`이면 모델에게 시키지 말고 코드로 처리한다.

## 2. 실패했을 때 — `rework_next` (같은 방식 재시도 금지)

검증이 실패하면 같은 프롬프트를 다시 던지지 않는다. `rework_next`를 부르고
받은 칸만 올린다. 한 번에 축 하나씩이다.

| 회차 | 칸 | 무엇이 바뀌나 |
|---|---|---|
| 2 | `retry` | 그대로. 증거(실패 테스트·diff)만 추가 |
| 3 | `widen` | 범위만 확대. 모델은 그대로 |
| 4 | `tier-up` | 모델 상승. 단 **진단 400토큰만**, 적용은 아래 티어 |
| 5 | `respec` | 구현 중단. 스펙 다시 쓰고 사람에게 |

**리워크 턴에서 파일 전문을 다시 쓰지 않는다.** 진단 몇 줄 + 통합 diff만
낸다. 이 비용의 81~92%가 출력 토큰이라 여기가 가장 큰 절감 지점이다.

### 의도불일치 — 분류가 모델 상승을 결정한다

사용자가 "이거 아닌데"라면 반려 사유를 `classify_mismatch`로 분류한다.
**티어를 올리는 건 오직 `reasoning`(판단 오류) 하나뿐**이다. 나머지는 티어를
올려도 안 고쳐지므로 절대 모델을 안 올린다.

| 종류 | 대응 칸 | 티어 상승? |
|---|---|---|
| `scope` 범위 어긋남 | `widen` | 아니오 |
| `taste` 취향·표현 | 같은 칸 변주 | 아니오 |
| `assumption` 숨은 전제 | `widen`(전제를 AC로) | 아니오 |
| `reasoning` 판단 오류 | `tier-up`(조건부) | **예** |
| `stale` 맥락 오염 | `reset` | 아니오 |

즉 "취향" 불일치에 LARGE 모델을 붙이는 건 돈만 쓰고 안 고쳐진다.

## 3. 비용의 지배항은 모델 터가 아니라 입력 누적이다

리워크가 길어지면 직전 턴의 출력과 사용자 발화가 다음 턴 입력에 **통째로
다시 실린다**. 실측 페르소나 A 입력은 79,130토큰까지 불어났고, 이것이
리워크 비용의 실제 지배항이었다.

- 그래서 사다리의 값어치는 "좋은 모델을 쓰는" 게 아니다.
- **입력 누적을 끊는 것**에서 나온다 — 바로 `reset` 칸이다.
- `reset`은 누적 컨텍스트를 버리고 새 세션을 열어 누적을 0으로 끊는다.
- `config.TURN_GROWTH_TOK = 4700` 은 그 역산값(오차 5.8%). 고정 입력으로
  계산하면 실제보다 약 절반 과소평가된다.

짧은 리워크(1~2턴)에서도 사다리는 제자리 재시도보다 싸다(26% / 45% 절감) —
단, 입력 누적을 끊는 `reset`이 함께 들어가야 한다.

## 4. 매 턴 끝 — `session_check`

- `continue` 그대로 진행
- `compact` 스레드는 유지하고 결론만 남긴다
- `reset` 새 세션. `carry_over`에 적힌 것만 들고 간다

**반복만으로는 리셋하지 않는다.** 리셋은 완료된 결과가 원하던 방향이
아닐 때만 나온다. 맥락을 부수는 비용이 크기 때문이다.

## 5. 설명 — `trim_explain`

"자세히 / 깊게 / 문서로"를 명시적으로 요청받지 않은 모든 설명은
`trim_explain`을 통과시킨다.
